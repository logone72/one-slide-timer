# 원 슬라이드 타이머 제품 스펙

## 목표

원 슬라이드 타이머는 모바일에서 한 번의 제스처로 병렬 타이머를 시작하는 웹앱이다. 시작 핀을 잡고, 원하는 시간까지 끌고, 놓으면 바로 타이머가 시작된다.

기존 타이머는 보통 하나의 카운트다운에 맞춰져 있다. 하지만 실제 업무와 생활에서는 여러 타이머가 동시에 필요하다. 예를 들면 요리 중 10분 뒤 파스타, 5분 뒤 계란, 30분 뒤 손님 도착을 함께 관리하거나, 업무 중 40분 집중, 15분 뒤 메신저 확인, 50분 뒤 미팅을 함께 챙기는 상황이다.

## 원칙

- 모바일 전용으로 먼저 만든다. PC에서도 앱 너비는 최대 430px로 제한하고 가운데 배치한다. 데스크톱 전용 화면은 초기 범위가 아니다.
- 웹을 기본 기술로 쓴다. 앱 배포가 필요해져도 웹앱/PWA를 먼저 두고, 네이티브 래핑은 나중에 검증한다.
- 시작은 한 번의 제스처로 끝낸다. 모달을 열고, 숫자를 입력하고, 시작 버튼을 누르는 흐름을 기본으로 두지 않는다.
- 여러 타이머가 동시에 떠 있는 상태를 정상 상태로 본다.
- 직접 조작이 기본이다. 타이머 핀을 드래그해서 만들고, 늘리고, 줄이고, 없앤다.
- 중요한 값은 설정 버튼으로 연 설정 화면에서 바꿀 수 있어야 한다.
- 하단 탭은 사용하지 않는다.
- 웹 배포를 먼저 만들어 실제 모바일 브라우저에서 써보고 테스트한다.
- 앱스토어 출시는 필수 목표다. 같은 웹앱을 Capacitor로 감싼 iOS 앱으로 배포한다.
- 모든 기능은 로컬에서 쉽게 테스트할 수 있어야 하고, 코드 가독성을 우선한다.
- lint, typecheck, 테스트, commitlint를 커밋 시점에 강제해 코드 품질을 낮추는 변경이 쉽게 들어오지 못하게 한다.
- 웹 MVP는 앱이 열린 동안의 반복 알림과 앱 복귀 시 완료 처리를 보장한다. 지원되는 브라우저에서는 권한 허용 후 웹 시스템 알림도 표시한다.
- 네이티브 알림은 iOS 연결 후 붙이되, 첫 구조부터 알림 어댑터 경계를 둔다.

## 첫 버전 범위

첫 버전은 카운트다운 레일을 기본 화면으로 둔다. 시간 범위 기본값은 1시간이고, 화면 구석의 설정 버튼으로 연 설정 화면에서 스테퍼와 슬라이더로 5분부터 55분까지 5분씩, 1시간부터 12시간까지 1시간씩 바꿀 수 있다. 24시간 알람 레일은 계산 기준이 달라서 뒤로 미룬다.

포함:

- 카운트다운 레일은 상하 방향이다. 아래가 0이고, 위로 드래그할수록 시간이 길어진다.
- 시작 핀을 0에서 위로 드래그하고 놓으면 카운트다운 타이머가 바로 시작된다.
- 시작 핀을 누르는 순간 미리보기 타이머가 생긴다. 빈 레일은 스크롤과 확대에 사용한다. 타이머 색상은 정해진 팔레트에서 순서대로 선택하며, 미리보기 색상이 실행 상태에서도 유지된다.
- 드래그 중에는 손가락에 가리지 않도록 타이머 라벨을 핀 옆에 표시한다.
- 타이머가 실행 중이어도 시작 핀은 항상 남아 있어 새 타이머를 또 만들 수 있다.
- 모든 활성 타이머 핀 옆에 남은 시간, 진행 상태, 종료 시각을 계속 표시한다.
- 레일에 0부터 설정한 시간 범위까지 숫자 눈금과 보조 눈금을 표시한다. 주요 눈금 간격은 1시간 미만에서 5등분, 1시간 이상에서 6등분한다.
- 타이머 라벨끼리 겹치지 않도록 간단한 줄 배치 규칙을 적용한다.
- 활성 타이머 핀을 탭하면 시간 조정과 조기 종료 액션을 보여준다. 시작 핀을 탭하면 시간 조정을 열어 드래그 없이도 타이머를 만든다.
- 활성 타이머 핀을 드래그해서 남은 시간을 늘리거나 줄일 수 있다.
- 활성 타이머 핀을 아래의 0 지점으로 드래그해서 놓으면 조기 종료 처리한다.
- 타이머가 완료되면 완료 알림이 울리고, 사용자가 확인할 때까지 계속 울린다.
- 여러 타이머가 완료되면 하나의 완료 알림으로 합치고, 완료된 타이머 목록을 함께 보여준다.
- 확인된 타이머는 사라진다.
- 첫 출시의 시간 정밀도는 10초 단위다.
- 화면 구석의 설정 버튼으로 설정 화면을 열 수 있다.
- 설정 화면에서 스테퍼와 슬라이더로 시간 범위를 5분부터 55분까지 5분씩, 1시간부터 12시간까지 1시간씩 바꿀 수 있다.
- 설정 화면에서 화이트·포레스트·오션·미드나이트 색상 테마를 선택할 수 있다. 기본값은 흰색 기반의 화이트이며 기존 라벤더 설정은 화이트로 전환한다. 선택 즉시 앱 전체에 적용하고 다시 열었을 때도 유지한다.
- 앱이 다시 열렸을 때 이미 종료 시각이 지난 타이머는 완료 알림 목록에 들어간다.
- PWA manifest에 고정 앱 식별자·실행 범위·192/512px 설치 아이콘을 지정한다. 기존 파비콘을 원본으로 일반·maskable 아이콘과 180px iOS 홈 화면 아이콘을 제공하고, 알림 표시·클릭 전용 서비스 워커를 둔다.
- 웹·iOS 모두 시작 시 권한을 조회하고, 시작 모달 또는 설정의 토글 켜기에서만 권한을 요청한다. 켜진 채널의 테스트 버튼을 제공한다.

첫 버전에서 제외:

- 알람 레일의 24시간 절대 시각 알람.
- 슬라이드 중 줌인되는 정밀 시간 설정.
- 후속 타이머.
- 시간 범위와 색상 테마 외의 깊은 커스텀 설정.
- 잠금 화면과 백그라운드에서의 네이티브 알림 보장.
- offline cache와 서버 Web Push. 웹앱 종료 후의 예약 알림 보장.

## 향후 범위

**알람 레일**:
한 줄이 24시간을 표현한다. 현재 시간 위치를 시간 레일 위에 표시한다. 현재 시간보다 이전 위치를 선택하면 오늘이 아니라 내일 울리는 알람 타이머로 본다.

**정밀 줌**:
처음에는 거친 범위로 시간을 잡고, 드래그가 이어질수록 해당 구간이 확대되어 더 정밀하게 시간을 고른다.

**후속 타이머**:
첫 버전 이후 후보 기능이다. 실행 중인 타이머 핀에서 다음 타이머를 만들 수 있다. 부모 타이머가 끝나면 후속 타이머가 시작된다. 부모 타이머의 시간이 늘어나면 후속 타이머는 그 완료 시점까지 계속 대기한다.

**타이머 이름**:
이름 없는 타이머를 정상 상태로 두고, 이름 추가 기능은 나중에 필요성이 분명해졌을 때 검토한다.

## 타이머 모델

카운트다운 타이머는 감소하는 카운터가 아니라 종료 시각을 저장한다. 남은 시간은 항상 `endAt - now`로 계산한다. 그래야 브라우저 탭 지연, 워커 갱신 지연, 화면 복귀 후에도 누적 오차가 커지지 않는다.

Web Worker는 종료 시각 목록을 받아 다음 숫자 변경 시점을 예약하고, UI에는 시각 값 없이 갱신 신호만 보낸다. 생성 실패나 실행 오류가 나면 메인 스레드에서 같은 예약 함수를 사용하며 중복 실행과 정리 후 재시작을 막는다. UI는 신호가 올 때마다 현재 시각 기준으로 남은 시간을 다시 계산한다. 신호를 믿고 숫자만 줄이지 않는다.

각 타이머의 숫자는 시작·시간 변경 시점 기준으로 1초마다 줄어든다. 갱신 신호는 가장 가까운 타이머의 초 경계에 맞추며, 서로 다른 시점에 시작한 타이머가 있으면 1초 안에 여러 신호가 올 수 있다. 예약은 하나만 유지하고, 콜백 지연 후에도 종료 시각에서 다음 경계를 다시 계산하여 오차를 누적하지 않는다. 타이머 핀·시간 라벨·연결선은 현재 위치부터 다음 1초의 위치까지 `transform`을 선형 보간해 연속으로 내려간다. 프레임 보간은 브라우저의 Web Animations API가 맡으며, 매 프레임 React 상태를 갱신하지 않는다. 드래그 미리보기는 즉시 위치를 적용하고, 시간 범위 변경·화면 복귀 시에는 현재 시각의 위치로 다시 맞춘다. 동작 줄이기 설정에서는 보간을 끈다.

타이머가 0에 도달하면 완료되고 완료 알림이 시작된다. 완료 알림은 사용자가 확인할 때까지 반복된다. 사용자가 완료 전에 0으로 끌어 놓으면 조기 종료다.

웹 시스템 알림은 앱이 실행 중일 때 기존 `endAt` 완료 판정에서 전달하며, 복귀하면 놓친 완료를 다시 확인한다. 같은 완료 목록을 매초 재전송하지 않고 같은 tag로 합쳐 표시한다. 알림음이 켜져 있으면 확인할 때까지 반복한다. HTTPS와 브라우저 알림 API가 필요하며, iPhone·iPad는 지원 버전의 홈 화면 웹앱에서 확인한다. 서비스 워커에 미래 타이머 실행을 맡기지 않는다.

웹앱 첫 버전에서는 앱이 열린 상태의 완료 알림을 먼저 보장한다. 잠금 화면, 백그라운드, 무음 모드에서의 동작은 브라우저와 OS 제약을 실제 기기에서 확인한 뒤 PWA 또는 네이티브 래핑 범위로 판단한다.

앱이 닫혀 있거나 백그라운드에 있다가 돌아오면 저장된 `endAt`을 현재 시각과 비교한다. 이미 끝난 타이머는 완료 알림 목록에 넣고, 앱이 열린 상태의 반복 알림을 시작한다.

## 인터랙션 스펙

### 타이머 시작

1. 사용자가 0 지점의 시작 핀을 누른다.
2. 미리보기 타이머가 생기며 위로 드래그해서 시간을 고른다.
3. 선택 시간은 현재 시간 범위 안에서 10초 단위로 맞춰진다.
4. 타이머 라벨은 손가락에 가리지 않도록 핀 옆에 선택된 시간을 표시한다.
5. 사용자가 손을 뗀다.
6. 미리보기 타이머가 실행 중인 카운트다운 타이머가 된다.

### 타이머 조정

1. 사용자가 활성 타이머 핀을 드래그한다.
2. 드래그 중 남은 시간이 10초 단위로 즉시 갱신된다.
3. 손을 떼면 기존 타이머의 ID와 색상을 유지한 채 새 종료 시각이 확정된다. 새 타이머는 만들지 않는다.
4. 0에서 손을 떼면 타이머를 없앤다.
5. 포인터 취소, Escape, 화면 이탈 시 편집을 취소하고 원래 종료 시각을 유지한다.
6. 키보드 위아래 화살표로 10초씩, Shift와 화살표로 1분씩 조정하며 Enter로 확정한다.
7. 드래그 대신 시작 핀의 탭·Enter·Space 또는 실행 중 타이머의 시간 조정 액션을 사용할 수 있다. 네이티브 슬라이더와 ±10초 버튼으로 선택하고 적용·취소 후 원래 핀으로 초점을 돌린다.

### 완료 알림

1. 카운트다운 타이머가 0에 도달한다.
2. 완료 알림이 울리고 화면에 확인 액션을 표시한다.
3. 완료 알림은 사용자가 확인할 때까지 반복된다.
4. 여러 타이머가 동시에 완료되면 하나의 완료 알림에 완료된 타이머 목록을 합친다.
5. 완료 알림이 울리는 중에 다른 타이머가 완료되면 같은 목록에 추가한다. 창을 다시 열거나 초점을 옮기거나 반복 알림음 주기를 재시작하지 않는다.
6. 앱 복귀 시 이미 끝난 타이머가 있으면 같은 완료 알림 목록에 추가한다.
7. 사용자가 확인하면 알림을 멈추고 목록 안의 타이머를 제거한다.

### 타이머 액션

1. 사용자가 활성 타이머 핀을 탭한다.
2. 핀 근처에 작은 액션 UI를 띄운다.
3. 시간 조정과 조기 종료를 제공한다. 시간 조정에서는 슬라이더 또는 10초 단위 버튼을 사용해 고른 값을 적용한다.
4. 바깥을 탭하면 닫는다.

### 라벨 겹침

타이머 라벨은 세로 위치순으로 정렬한 뒤, 레일 안에서 최소 간격을 유지하도록 위아래로 배치한다. 라벨과 실제 타이머 핀 위치는 연결선으로 표시한다. 타이머가 많아지면 레일의 최소 높이를 늘리고 화면을 스크롤할 수 있게 한다. 라벨을 잡아 조정해도 잡은 위치부터 상대적으로 시간을 변경한다. 글자 확대 시 실제 카드 높이를 다시 측정하고, 최소 높이와 카드 사이 간격을 함께 반영한다.

### 설정

1. 사용자가 화면 구석의 설정 버튼을 탭한다.
2. 앱 영역 전체를 차지하는 설정 화면이 열린다. 키보드 초점은 설정 화면 안에 유지하고, 닫으면 설정 버튼으로 돌려준다.
3. 시간 범위를 스테퍼와 슬라이더로 5분부터 55분까지 5분씩, 1시간부터 12시간까지 1시간씩 바꾼다.
4. 변경값은 새로 만드는 타이머의 시간 레일 위치 계산에 적용된다.
5. 이미 실행 중인 타이머는 종료 시각을 유지하고, 새 시간 범위에 맞춰 위치만 다시 계산한다.
6. 스테퍼와 슬라이더는 5분 아래와 12시간 위로 값이 넘어가지 않게 막는다. 55분 다음은 1시간, 1시간 다음은 2시간이며 반대 방향도 같은 경계를 따른다.
7. 색상 테마는 미리보기 카드와 라디오 버튼으로 선택한다. 선택 즉시 타이머·설정·완료 알림·브라우저 색상에 적용하고 키보드 화살표로도 선택할 수 있다.
8. 시간 범위와 테마를 로컬에 저장한다. 이전 시간 단위 설정은 분 단위 `rangeMinutes`로 변환하며, 기존 타이머의 ID와 종료 시각은 유지한다. 타이머 색상은 같은 팔레트 순번의 테마 토큰에 연결한다.

## 시각 방향

시스템 폰트, 흰색 기반 기본 테마, 절제된 표면을 기준으로 삼는다. 소개 영역 없이 브랜드·설정 버튼 아래에 타이머 상태와 레일을 배치한다. 시작 핀은 가장 뚜렷한 채움색을 사용하며, 타이머 라벨은 큰 시간 숫자를 먼저 읽게 한다. 타이머별 색상은 핀·연결선·6px 너비의 카드 왼쪽 테두리에 사용한다. 카드의 드래그 아이콘은 세로 중앙에 정렬한다. 화이트·포레스트·오션·미드나이트는 같은 구성과 상태 구분을 유지하며 팔레트를 바꾼다.

색상·간격·타이포그래피·크기·아이콘·그림자·모션은 [디자인 토큰](design-tokens.md)으로 관리한다. 레일 라벨 배치 계산도 CSS 토큰의 크기를 읽어 사용한다.

참고: [16 little UI design tips](https://www.adhamdannaway.com/blog/ui-design/ui-design-tips), [14 logic-driven UI design tips](https://www.adhamdannaway.com/blog/ui-design/ui-design-tips-14). 관련 요소를 여백으로 묶고, 핵심 행동의 위계를 세우며, 색상 외의 선택 표시와 충분한 대비·터치 영역을 제공하는 원칙을 적용한다.

시간 레일과 타이머 핀이 화면의 주인공이어야 한다. 영문 장식 문구와 반복되는 장식 모션을 줄인다. 시작 핀의 위쪽 화살표와 "끌어서 시작" 안내, 미리보기의 점선 테두리와 "놓으면 시작/변경" 안내, 실행 중인 타이머의 "진행 중" 문구로 상태를 구분한다. 시작 핀의 확산 모션은 처음 두 번만 재생하며, 실제 카운트다운 이동은 계속 유지한다. 동작 줄이기 설정에서는 애니메이션을 끈다.

빈 레일의 안내 화살표는 위로 끄는 방향을 반복해서 보여준다. 타이머를 누르면 핀·카드가 반응하고, 끌 때는 미리보기가 살짝 확대되며, 놓으면 짧은 착지 모션을 재생한다. 이 피드백은 초 단위 위치 보간과 분리하며 동작 줄이기 설정에서는 끈다.

설정 버튼은 아이콘과 "설정" 이름을 함께 표시한다. 설정 화면은 시간 범위·색상 테마·사용 방법을 여백으로 묶고, 스크롤 중에도 뒤로 가기와 제목이 보이도록 한다. 테마 선택은 윤곽과 체크 표시로 구분하며, 설정값이 자동 저장됨을 표시한다. 글자 크기·대비·터치 영역 기준은 디자인 토큰 문서를 따른다.

## 기술 계획

권장 스택:

- Vite + React + TypeScript
- npm
- Node 24
- GitHub Pages 웹 배포
- XState로 레일의 제스처·타이머 액션·시간 조정 화면 전환 제어
- Zustand로 앱 전체 공유 상태와 변경 액션 관리. 앱 인스턴스별 store 하나를 사용한다.
- Web Worker로 타이머 갱신 신호 처리
- localStorage로 첫 버전의 타이머와 설정 영속성 처리
- ESLint, Prettier, TypeScript strict, Vitest로 로컬 품질 검증
- Playwright로 배포 전 browser smoke 검증
- Husky, lint-staged, commitlint로 커밋 시점 품질 게이트 적용
- Conventional Commits 형식 사용
- `@/` 경로 별칭으로 `src/` 내부 import 정리
- DOM/CSS와 Pointer Events로 시간 레일 구현
- PWA manifest와 iOS 홈 화면 메타태그
- 웹 배포를 먼저 만들고, 앱스토어 출시는 Capacitor iOS 앱으로 진행
- Android는 추가 가능하게 열어두되, 첫 네이티브 폴더는 `ios/`만 생성

앱 식별자:

- 앱 표시 이름: `One Slide Timer`
- Capacitor `appName`: `One Slide Timer`
- Capacitor `appId`: `com.roegankim.oneslidetimer`

앱 상태 관리 구조는 Zustand가 타이머·설정·알림·앱 화면 상태를 소유하고, 앱 실행 계층이 저장·Worker·오디오·플랫폼 API 연결을 담당한다. XState와 로컬 입력·DOM 상태의 경계는 유지한다. [전체 적용 계획](zustand-state-management-plan.md)의 소유권 표에 따라 구현했으며 기존 상태 훅은 제거했다.

레일과 타이머 상태 모델:

- 레일 상호작용: `idle`, `creatingTimer`, `editingTimer`, `showingTimerActions`, `adjustingTime`
- 타이머: 저장 필드는 `id`, `createdAt`, `endAt`, `color`다. `endAt > now`면 진행 중, 아니면 완료이며 확인·조기 종료하면 목록에서 제거한다. 미리보기는 제스처 상태에만 둔다.

상태 머신은 레일의 제스처·타이머 액션·시간 조정 화면 전환을 책임진다. 시간 조정 화면 진입은 이전 미리보기와 메뉴 선택을 정리한다. 조정 중인 기존 타이머가 완료되면 조정 상태도 정리한다. 조정 화면의 입력값은 로컬 상태로 두며 타이머 목록은 머신에 복제하지 않는다. 포인터·키보드·시간 조정의 확정은 머신에서 한 번만 처리하고 기존 타이머 생성·수정 콜백에 위임한다. 시간 계산, 좌표 변환, 10초 스냅, 라벨 배치는 순수 함수로 둔다. 렌더링은 시간 레일 위치와 타이머 핀 목록을 받아 그리는 얇은 계층으로 둔다.

알림 경계:

- 웹 MVP는 브라우저 오디오 반복과 앱 복귀 시 완료 처리를 구현한다.
- 웹·iOS는 시작 시 기기 알림 권한과 저장된 알림음 사용 선택을 확인한다. 둘 중 하나라도 OFF이고 `다시 묻지 않기`를 선택하지 않았으면 `완료 알림 설정`에서 공통 토글을 제공한다. `완료`는 이번 실행의 안내를 닫고, 하단 `다시 묻지 않기`는 이후 실행에서도 안내를 숨긴다. 기기 알림 미지원과 명시적인 OFF도 안내 대상이며, OS 권한 요청은 토글 켜기에서만 수행한다.
- 설정의 기기 알림과 알림음은 같은 공통 토글 UI를 사용한다. 알림음 선택은 `audioEnabled`로 저장하며 기본값은 켜짐이다. 끄면 재생 중인 소리와 반복을 즉시 멈추고 다음 타이머에도 적용한다. 새로고침해도 ON/OFF를 유지하며 재생 준비 실패는 사용 선택을 바꾸지 않는다. 소리 테스트도 사용 선택을 바꾸지 않는다.
- 네이티브 권한이 거부되어도 켜둔 알림음은 독립적으로 동작한다. 알림음이 ON이면 새 타이머 등록 조작에서 브라우저 오디오를 준비한다. 등록 시에는 소리를 내지 않고 완료 시 재생한다. 새로고침 후 사용자 조작 없이 기존 타이머가 완료되면 브라우저 정책에 따라 소리가 나지 않을 수 있다. 기기 알림 권한 조회 실패는 해당 토글을 OFF로 표시하며 별도 확인·복구 버튼을 두지 않는다.
- `platform/notifications`는 `ensurePermission`, `scheduleTimer`, `cancelTimer`, `onNotificationAction` 형태로 둔다.

## 개발 계획

상태 구조 개선은 [Zustand 기반 앱 전체 상태 관리 계획](zustand-state-management-plan.md)을 따른다. 기존 기능의 상태·저장·실행 수명을 먼저 이전하고 검증한 뒤 새 알림 권한 기능을 연결했다.

알림 권한과 설정의 계약은 [알림 권한과 설정 UI 개발 계획](notification-permissions-plan.md)에 정리한다. 앱 시작 시 조회·안내와 토글 켜기 요청, 공통 토글과 영구 안내 숨김, 권한 조회·요청 분리, 앱 복귀와 예약 취소·복구를 다루며 구현과 자동 검사를 완료했다. iOS 실기기 검증은 남아 있다.

1. 모바일 웹앱 스캐폴딩과 모바일 뷰포트 기준 UI 셸 작성.
2. Node 24, npm, GitHub Pages, PWA manifest, iOS 홈 화면 메타태그를 설정한다.
3. ESLint, Prettier, TypeScript strict, Vitest, Playwright, Husky, lint-staged, commitlint를 설정한다.
4. 종료 시각 기반 카운트다운 타이머 모델과 Web Worker 갱신 신호 구현.
5. DOM/CSS 시간 레일, 시작 핀, 미리보기 타이머, 놓으면 바로 시작되는 흐름 구현.
6. 설정 버튼과 시간 범위 설정 구현.
7. 여러 활성 타이머와 타이머 라벨 충돌 회피 구현.
8. 활성 타이머 핀 드래그 편집과 0 지점 조기 종료 구현.
9. 타이머 핀 탭 액션으로 조기 종료 구현.
10. localStorage 저장과 화면 복귀 시 완료 재계산 처리.
11. 웹 배포 환경을 만들고 실제 모바일 브라우저에서 타이머 정확도와 완료 알림을 확인.
12. Capacitor iOS 프로젝트를 연결하고 App Store 빌드 경로를 검증.
13. iOS에서 Local Notifications 연동과 앱 시작 시 권한 조회·안내, 사용자 확인 후 권한 요청을 검증.
14. 백그라운드, 잠금 화면, 무음 모드 알림 동작을 실제 기기에서 조사.
15. 후속 타이머의 첫 버전 이후 설계 여부 결정.
16. 알람 레일 추가 여부 결정.

## 저장과 오류 복구

- 저장소가 비어 있는 경우와 읽기·구문·검증 실패를 구분한다. 실패한 기존 값은 덮어쓰지 않는다.
- 저장에 실패해도 현재 화면의 타이머 생성·조정·완료는 계속 동작한다. 오류 안내와 재시도 버튼을 타이머·설정·완료 화면에서 제공한다.
- 읽기 복구 시 기존 타이머와 오류 중 만든 타이머를 ID로 합친다. 설정은 오류 중 사용자가 바꾼 필드만 우선하고 나머지 저장값을 보존한다.
- 이전 `running`·`alerting` 상태는 제거하고 ID·종료 시각을 보존한다. `dismissed` 타이머는 복원하지 않는다.
- 시간 범위 허용값은 `RANGE_MINUTE_OPTIONS`를 공통 기준으로 사용한다. 저장값 보정과 스테퍼·슬라이더가 같은 목록을 따른다.
- 같은 타이머 ID의 예약·취소를 순서대로 처리한다. 무효 예약 취소는 권한 확인을 기다리지 않으며 새 예약만 권한을 확인한다. 대기 중 삭제하거나 다시 조정한 타이머의 오래된 예약은 남기지 않는다. 삭제 후 취소에 실패한 알림도 재시도 대상에 포함한다.
- 네이티브 이벤트 구독은 해제하며, 구독 등록이 늦게 끝나도 이미 닫힌 구독은 제거한다. 권한 거부와 플러그인 오류는 복구 안내로 전달하고 재시도 시 이벤트 구독도 다시 연결한다.
- 오디오 활성화 여부는 실제 오디오 상태에서 읽는다. 브라우저가 오디오를 중단하거나 종료하면 재활성화 버튼을 다시 제공한다.
